# Waylist

**Меньше суеты, больше путешествий.**

Адаптивное PWA для планирования автомобильных поездок. Главный экран маршрута — вертикальный таймлайн: **точка → участок пути → остановка**. Расстояние, время и навигационные ссылки задаются вручную. Приложение не строит автомобильные маршруты и не заменяет навигатор.

## Возможности

- Регистрация и вход по email/паролю; одноразовая ссылка для входа через SMTP.
- Dashboard: поиск, сортировка, создание, дублирование, архивирование и удаление поездок.
- Создание старта/финиша и промежуточных точек; типы остановок, адреса, координаты, время, описание, заметки и внешние ссылки.
- Копирование точек, поиск внутри маршрута, изменение порядка мышью, касанием, клавиатурой и кнопками вверх/вниз.
- Автоматическое создание сегментов между соседними точками. Неизменённые направленные пары сохраняют данные; сброс заполненных сегментов требует подтверждения.
- Ручное редактирование километров, минут, заметок и навигационных ссылок для Yandex / Google / Apple / Other. Сохранённые URL открываются без изменения.
- Подсчёт общей дистанции, времени движения, остановок и всей поездки, числа точек/участков.
- Заметки на уровне поездки, точки и сегмента.
- Живая публичная ссылка с просмотром без регистрации; отправка приглашения по email.
- JSON-экспорт и обратный импорт с валидацией и новыми идентификаторами.
- Вспомогательная **схема** точек по координатам, без картографических API и геокодинга.
- PWA: manifest, иконки, service worker, уведомление об обновлении, offline-доступ и локальное редактирование ранее загруженных поездок.
- Очередь синхронизации; при конфликте серверной и локальной версий требуется явный выбор пользователя.

## Стек и архитектура

| Часть | Реализация |
| --- | --- |
| Интерфейс | React 19, TypeScript, Vite, CSS, Lucide |
| Перестановка точек | dnd-kit, включая клавиатурный сенсор |
| Состояние | React hooks + `useSyncExternalStore` |
| Локальные данные | IndexedDB через `idb-keyval` |
| PWA | `vite-plugin-pwa`, Workbox |
| API | Node.js, Express 5, TypeScript |
| Серверная БД | SQLite через встроенный `node:sqlite`, WAL |
| Валидация | Zod на клиенте и сервере |
| Авторизация | bcrypt, случайные session tokens, HttpOnly cookies |
| Email | Интерфейс `EmailService`, SMTP-адаптер на Nodemailer |
| Проверки | TypeScript, Vitest, Playwright |

**Почему без Redux/Saga:** для текущего MVP достаточно React и небольшого внешнего хранилища с последовательной очередью операций. Дополнительная библиотека управления состоянием не требуется.

**Почему SQLite, а не PostgreSQL/ORM:** это самостоятельный однопроцессный MVP без внешней БД и отдельной инфраструктуры. Пользователи, сессии, magic tokens, поездки и публичные ссылки сохраняются на сервере. Поездка хранится как JSON-агрегат вместе с владельцем и версией; точки и сегменты пока не вынесены в отдельные таблицы. При масштабировании потребуются миграции, PostgreSQL и выделенный слой репозитория.

## Быстрый запуск

Требуется **Node.js 22.13+**; рекомендуется актуальная Node.js 24 LTS. В старых версиях Node нет нужного `node:sqlite`. На некоторых версиях Node модуль выводит предупреждение об экспериментальном статусе.

```sh
npm ci
npm run dev
```

- Интерфейс: **http://localhost:5173**.
- API: **http://localhost:3001/api**.
- Vite проксирует `/api` на сервер; cookies остаются same-origin.
- База `data/waylist.sqlite` создаётся автоматически.
- Готовых аккаунтов и демонстрационных паролей нет: зарегистрируйтесь в интерфейсе.
- `.env` необязателен для локального входа по паролю. Для почты скопируйте `.env.example` в `.env` и заполните SMTP-параметры.

```sh
cp .env.example .env
```

Команда `npm run dev` запускает оба процесса и завершает их вместе. Порт API в Vite-прокси задан в `vite.config.ts`: при изменении `PORT` обновите и прокси.

> Для открытия с телефона по LAN нужен корректный `APP_URL` и HTTPS: service worker и `crypto.randomUUID()` требуют secure context. Исключение браузера для HTTP действует на `localhost`, но не на произвольный LAN-адрес. Первый запуск проще проверить на компьютере через localhost.

## Переменные окружения

`npm run dev:api` и `npm start` читают `.env` через Node `--env-file-if-exists`.

| Переменная | По умолчанию / назначение |
| --- | --- |
| `PORT` | `3001` — порт API |
| `APP_URL` | `http://localhost:5173` — публичный origin для ссылок и проверки Origin |
| `DATABASE_PATH` | `data/waylist.sqlite`, относительно корня проекта; допустим абсолютный путь |
| `NODE_ENV` | В `production` сервер раздаёт `dist/`, требует HTTPS `APP_URL`, использует Secure cookie |
| `TRUST_PROXY_HOPS` | Не задан; число доверенных reverse-proxy hops, задавайте только для известной инфраструктуры |
| `SMTP_HOST` | Хост SMTP; вместе с `SMTP_FROM` включает почту |
| `SMTP_PORT` | `587`; для `465` используется implicit TLS |
| `SMTP_USER` | Логин SMTP, если сервер требует авторизацию |
| `SMTP_PASS` | Пароль SMTP |
| `SMTP_FROM` | Адрес отправителя, разрешённый вашим почтовым провайдером |
| `SMTP_REQUIRE_TLS` | TLS обязателен; `false` допустимо только для локального тестового SMTP |

При отсутствии SMTP регистрация по паролю, поездки и публичные ссылки работают. Отправка email и magic link возвращают понятную ошибку `503`, а не имитируют доставку. Magic link действует 15 минут и используется один раз.

Почтовый сервис получает email получателя, название, описание и краткие данные поездки, ссылку и email отправителя. Стоимость и лимиты зависят от выбранного SMTP-провайдера. Ключи и пароли нельзя включать в клиентскую сборку или коммитить; `.env` исключён из Git.

### Браузерные тесты

Однократно установите Chromium:

```sh
npx playwright install chromium
npm run test:e2e
```

Если нужно хранить браузер внутри проекта:

```sh
PLAYWRIGHT_BROWSERS_PATH=.cache/ms-playwright npx playwright install chromium
PLAYWRIGHT_BROWSERS_PATH=.cache/ms-playwright npm run test:e2e
```

Playwright сам запускает тестовый API и preview production-сборки на портах **3001** и **4173**, затем завершает процессы. Эти порты должны быть свободны. Используется отдельная БД `data/e2e.sqlite`; тест создаёт уникальный аккаунт и не затрагивает основную БД. Артефакты ошибок — в `test-results/`.

Проверены:

- **22 unit/API-теста**: перестройка графа, сохранность сегментов, агрегаты, импорт, валидация, offline-очередь, конфликты, авторизация, владение, optimistic concurrency, живые ссылки и недоступность SMTP.
- **1 end-to-end тест Chromium**: регистрация, поездка, остановка, участок и navigation URL, JSON-скачивание, анонимный просмотр, offline-редактирование и перезагрузка, восстановление связи, обновление общего маршрута, отсутствие горизонтального переполнения при ширине 390 px.
- Production-сборка и проверка типов.

Реальная доставка почты через внешний SMTP и установка на физических iOS/Android-устройствах требуют проверки в вашей среде.

## PWA и offline

Service worker активируется в **production-сборке**, а не в обычном Vite dev-сервере. Он кеширует оболочку приложения и статические ресурсы, но **не кеширует приватные API-ответы** в общем HTTP-кеше.

Для локальной ручной проверки production-сборки:

1. `npm run build`.
2. В одном терминале: `APP_URL=http://localhost:4173 npm run dev:api`.
3. В другом: `npx vite preview --host localhost --port 4173 --strictPort`.
4. Откройте `http://localhost:4173`, войдите, создайте поездку и дождитесь синхронизации.
5. Дождитесь установки service worker; отключите сеть и перезагрузите страницу.
6. Откройте поездку, внесите изменения, включите сеть и дождитесь отправки очереди.

Установка — через меню браузера «Установить приложение» / «На экран Домой»; доступность команды зависит от браузера. Обновление service worker предлагается явно, чтобы не перезагрузить несохранённую форму автоматически.

### Как синхронизируются данные

1. Сохранение сначала записывает поездку и изменение в IndexedDB под ключом пользователя.
2. Каждое изменение содержит исходную серверную версию `baseUpdatedAt`.
3. Синхронизация запускается после локального изменения, при загрузке, восстановлении соединения, каждые 60 секунд в открытом приложении и кнопкой «Обновить».
4. Сервер сравнивает версию при сохранении **и удалении**. Несовпадение возвращает `409`.
5. Конфликт не перезаписывается молча: выберите серверную или локальную версию. Перед заменой можно экспортировать локальный маршрут.
6. Ошибка сети не очищает очередь; ошибки авторизации требуют повторного входа.

Ограничения offline-first MVP:

- Первый вход, открытие новой публичной ссылки, SMTP и синхронизация требуют сети.
- Offline-доступ предназначен для ранее загруженных поездок владельца; публичные маршруты отдельно в IndexedDB не сохраняются.
- После закрытия приложения фоновая отправка очереди не выполняется: откройте приложение снова.
- Нет автоматического слияния отдельных полей, CRDT и координации одновременного редактирования в нескольких вкладках. Работайте с аккаунтом в одной вкладке; конкурирующие серверные изменения с других устройств обнаруживаются по версии.
- Локальные данные не шифруются и сохраняются после выхода, чтобы не уничтожить несинхронизированные правки. На общем устройстве удаляйте данные сайта после завершения работы. Очистка данных браузера удаляет неотправленные изменения — делайте JSON-backup.
- Выход требует доступного API для завершения серверной сессии.

## Модель маршрута и импорт

Основной агрегат:

```text
Trip
├── Points[]   — точки с order, типом, координатами, временем и заметками
└── Segments[] — направленные участки между соседними точками
```

Единицы: `distance` — **километры**, `duration` — **минуты**, координаты — десятичные градусы. Время движения и остановок суммируется отдельно; arrival/departure — вручную заданные метки, автоматически из длительности не рассчитываются.

- При перестановке сохраняются только сегменты с той же **направленной** парой `fromPointId → toPointId`.
- Для новой пары создаётся пустой сегмент: старую navigation URL нельзя автоматически переносить на другой маршрут.
- Добавление или удаление точки также может изменить соседние участки и потребовать подтверждения.
- Импорт принимает полный JSON-экспорт этой версии, а не произвольный GeoJSON/GPX или сокращённый пример из спецификации.
- Новые ID создаются для поездки, точек и сегментов; импорт не перезаписывает существующие поездки и не копирует share link.
- Проверяются граф, ссылки только HTTP(S), числовые диапазоны, дубликаты и парность координат.
- Лимиты: 100 поездок на аккаунт, до 500 точек, до 30 внешних ссылок у точки, тело API до 2 MiB; интерфейс импорта ограничивает файл 2 МБ.

Тип `CUSTOM` позволяет создать произвольную остановку с собственным названием; отдельного пользовательского справочника типов в MVP нет.

## Публичный доступ и безопасность

- Ссылки `/share/:token` показывают актуальную **синхронизированную** поездку без входа. Все описания, адреса и заметки становятся видны обладателю ссылки.
- Ссылка — секрет доступа, а не поисковая публикация. Передавайте её только нужным людям. Сейчас она действует до удаления поездки; интерфейса отзыва или ротации ссылки пока нет.
- Чужие поездки нельзя изменять через API: владелец проверяется на сервере.
- Пароли хешируются bcrypt; в БД хранятся только хеши session/magic tokens. Сессия действует 30 дней.
- Cookies: HttpOnly, SameSite=Lax, Secure и `__Host-` в production. Изменяющие запросы проверяют Origin и Content-Type.
- Есть валидация тела запросов, ограничения размера, throttling, `nosniff`, запрет iframe и `Referrer-Policy: no-referrer`.
- Внешние навигационные ссылки открываются с `noopener noreferrer` и могут передавать данные соответствующему картографическому сервису только при переходе пользователя.
- Это не полностью подготовленный многопользовательский SaaS: до публичного запуска добавьте мониторинг, резервное копирование, политику персональных данных и внешние ограничения нагрузки.

## Развёртывание

```sh
npm ci
npm run build
NODE_ENV=production APP_URL=https://your-domain.example npm start
```

`your-domain.example` — пример: замените на реальный HTTPS-origin. TLS завершайте на доверенном reverse proxy; весь сайт, включая `/api`, должен быть доступен с одного origin. Настройте `TRUST_PROXY_HOPS` только если понимаете цепочку прокси.

- Сервер отдаёт `dist/` и SPA fallback для `/share/...` и `/auth/magic`.
- Нужен постоянный writable volume для `data/`. Не размещайте SQLite на эфемерной файловой системе serverless-функций.
- Используйте **один экземпляр** API с этой SQLite-БД. In-memory rate limit не распределён между процессами.
- Для согласованной резервной копии используйте SQLite backup API/инструменты либо останавливайте сервер перед копированием БД; простое копирование одного `.sqlite` при активном WAL может пропустить данные.
- `tsx` нужен при запуске сервера: текущий сценарий deployment требует установки devDependencies, а не `npm ci --omit=dev`.
- SMTP настраивается отдельно. Не раздавайте `.env`, `data/` или исходники как публичные статические файлы.

## Структура проекта

```text
src/
  App.tsx             Авторизация, dashboard и общий layout
  TripView.tsx        Таймлайн, схема и формы редактирования
  model.ts            Типы, валидация, перестройка графа, импорт и агрегаты
  storage.ts          IndexedDB, очередь синхронизации и React-store
  ui.tsx              Общие элементы интерфейса
  config.ts           Название, описание и цвет приложения
  main.tsx            Запуск React и обновление PWA
  styles.css          Адаптивные стили и печатное представление
  *.test.ts           Тесты модели и хранилища
server/
  index.ts            REST API, сессии, SQLite, sharing
  schema.ts           Валидация запросов и графа маршрута
  email.ts            Контракт EmailService и SMTP-адаптер
  *.test.ts           API- и schema-тесты
public/               Favicon и PWA-иконки
e2e/                  Браузерный сценарий (Playwright)
vite.config.ts        Vite, API proxy, PWA manifest и precache
playwright.config.ts  Браузерная среда и тестовые серверы
```

Название для UI, писем и PWA задаётся в `src/config.ts`; при ребрендинге также замените статический fallback title в `index.html` и графические иконки.

## Что оставлено за рамками MVP

Настоящая интерактивная карта и поиск мест через API, автоматическая маршрутизация, рекомендации, AI, OAuth, совместное редактирование с ролями, пользовательские обложки, CSV/GPX/PDF-экспорт как отдельные форматы, swipe-жесты и полноценное разрешение конфликтов. Для простой печати есть print CSS; отдельного генератора PDF нет.

Эти возможности не имитируются: в интерфейсе нет заглушек, выдающих неподключённый сервис за рабочий.
